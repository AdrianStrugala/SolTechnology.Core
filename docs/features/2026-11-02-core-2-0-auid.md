# SolTechnology.Core 2.0 — AUID

> Historical delivery record. It may not describe the current system.

## Goal

Deliver the 2.0 hardening of `SolTechnology.Core.AUID` end-to-end, as one library of the SolTechnology.Core 2.0
flagship release. Success means:

- `Auid` formats culture-invariantly and `TryParse` range-checks every part (`B10`, `B11`). The Polish overflow message stays verbatim as a kept joke (Guide §9.10; user, 2026-11-03).
- The JSON and type converters follow the framework contracts (P-08), and the docs state the real uniqueness bound and ordering.
- `Auid` and its converters live in `SolTechnology.Core.AUID`; the static `Auid.TimeProvider` is replaced by `TimeProvider` overloads (`C-08`, `C-09`).
- AUID ships XML docs, a `docs/AUID.md` README that compiles against 2.0, and conforms to the Coding Guide.

## Completion summary

Delivered on `master` between `54683c91` and the retrospective commit (2026-11-03); every step's
acceptance criteria were verified with the commands they name. Current behaviour and rationale live
in [`docs/architecture/auid.md`](../architecture/auid.md); consumer usage in [`docs/AUID.md`](../AUID.md).

- **01 — B10, B11, RM-11.** `ToString` formats with the invariant culture, and `TryParse` rejects a
  time before 2001-01-01 or after 2137-02-07 06:28:15 UTC instead of letting it overwrite the code
  bits. `ToString_UnderCulture_RoundTrips` (`th-TH`, `ar-SA`), `TryParse_OutOfRange_ReturnsFalse`
  (2000, 2138) and `TryParse_1xThaiCalendarString_ReturnsFalse` (literal
  `CTY_25671205123456_012345`, produced by the `4097d47f` code under `th-TH`) failed on that code and
  pass. The core brief's `auid 01` release-notes input now uses the RM-11 wording. The Polish
  overflow message is unchanged.
- **02 — P-08 (`logging-cache#22`, `#13`, `#25`).** `AuidJsonConverter` throws `JsonException` for
  invalid and empty strings (System.Text.Json adds the path, e.g. `$.Id`) and supports
  `Dictionary<Auid, T>` keys. `AuidTypeConverter.ConvertFrom` throws `NotSupportedException` naming
  the value. `docs/AUID.md` states the collision bound and that ordering holds only within one code.
- **03 — C-08, C-09 (`logging-cache#10`, `#12`).** `Auid`, `AuidJsonConverter` and
  `AuidTypeConverter` live in `SolTechnology.Core.AUID`; both converters are `sealed`. The static

## Post-completion review fixes (2026-11-03)

An independent code review of the completed feature found three issues; the fixes are on `master`.

- **A1 — finding:** `Auid.Encoding.cs` `CreateInternal` accepted a clock before the 2001-01-01
  epoch: the negative seconds were masked into the time bits and produced a wrong, valid-looking ID.
  **Fix:** `seconds < 0` throws `InvalidOperationException` with a separate English message
  ("AUID timestamp underflow: the clock is before the AUID epoch 2001-01-01T00:00:00Z."); the Polish
  2137 overflow message is untouched (Coding Guide §9.10). **Test:**
  `AuidNewTests.New_ClockBeforeEpoch_Throws` (default `FakeTimeProvider`, 2000-01-01) failed before
  and passes.
- **A2 — finding:** the timestamp used `GetUtcNow().Ticks`, which are the ticks of the offset-local
  clock time when a `TimeProvider` returns a non-zero offset, so the encoded time and the overflow
  check shifted by the offset. **Fix:** `GetUtcNow().UtcTicks`. **Tests:**
  `New_ClockWithNonZeroOffset_EncodesUtcTime` (+02:00 clock encodes the UTC time) and
  `New_OverflowCheck_IsOffsetIndependent(-12/+14)` (the last valid UTC second does not throw, the
  next one throws the Polish message, in both offsets) failed before (3 cases) and pass.
- **A3 — finding:** `AuidTypeConverter.ConvertFrom` threw `NotSupportedException` for an invalid
  string; MVC model binding reports "The value 'x' is not valid…" only for `FormatException`/
  `OverflowException`, so 2.0 lost that message. **Fix:** it throws `FormatException` again (1.x
  behaviour), still naming the value. **Test:** `AuidTypeConverterTests.ConvertFrom_Invalid_ThrowsNotSupportedExceptionWithValue`
  became `ConvertFrom_Invalid_ThrowsFormatExceptionWithValue`; it failed before and passes.
  `docs/AUID.md` and `docs/architecture/auid.md` converter tables updated; the P-08 amendment above
  is corrected.
