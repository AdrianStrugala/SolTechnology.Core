# SolTechnology.Core 2.0 — CQRS

> Historical delivery record. It may not describe the current system.

## Goal

Deliver the 2.0 hardening of `SolTechnology.Core.CQRS` end-to-end, as one library of the SolTechnology.Core 2.0
flagship release. Success means:

- A missing handler fails with a descriptive error, and dispatch goes through interfaces instead of reflection on concrete types.
- `LoggingPipelineBehavior` logs a failed `Result` as a failure with the error type and message only (L-01, RM-15).
- CQRS ships XML docs, a `docs/CQRS.md` README that compiles against 2.0, and conforms to the Coding Guide.

## Completion summary

Delivered on `master` between `9b2329db` and the retrospective commit (2026-11-03); every step's
acceptance criteria were verified with the commands they name. Current behaviour and rationale live
in [`docs/architecture/cqrs.md`](../architecture/cqrs.md); consumer usage in [`docs/CQRS.md`](../CQRS.md).

- **01 — resolution test.** `ModuleResolutionTests` builds a provider with `ValidateOnBuild` and
  `ValidateScopes`, resolves the mediator, both event seams, a command, query and event handler, a
  validator and the behaviors in a scope, and sends a query. CQRS had no known-broken registration,
  so nothing is ignored.
- **02 — dispatch (`cqrs-tale#10`, `cqrs-tale#20`).** A missing handler throws
  `InvalidOperationException` naming the request type and the `RegisterCommandsFromAssembly` /
  `RegisterQueriesFromAssembly` call (internal handlers are not discovered). Behaviors and event
  handlers run through their interfaces by delegates cached per type, so explicit implementations
  work and synchronous throws are not wrapped. The dispatcher cache is keyed by request type and
  handler interface, and each `Send` overload names its handler interface, so a type implementing
  `IQuery<T>` and `ICommand<T>` reaches both handlers. Seven new tests failed on the old code.
- **03 — L-01, RM-15 (`cqrs-tale#11`, `cqrs-tale#26`).** A failed `Result` writes one Warning entry,
  EventId 2149 `OperationFailedWithResult`:
  `Operation: [{OperationName}]. Status: [FAIL]. Duration: [{DurationMs} ms]. ErrorType: [{ErrorType}]. ErrorMessage: [{ErrorMessage}]`,
  and sets the activity status to `Error`. Only the `Error` type name and `Error.Message` are logged.
  Success, `[LogScope]` masking and the RM-15 shape are pinned by tests.
- **04 — XML docs (`P1-4`, `cqrs-tale#16`).** `GenerateDocumentationFile` is on; the packed
  `SolTechnology.Core.CQRS.2.0.0.nupkg` contains `lib/net10.0/SolTechnology.Core.CQRS.xml` and the
  new readme.
- **05 — module docs.** `docs/CQRS.md` follows the public documentation structure and describes the
  2.0 behaviour (`AddSolCQRS`, sequential event dispatch in one scope per event, behavior order, the

  the RM-15 note; the solution's Docs folder lists `docs/CQRS.md`.
- **06 — Guide conformance (`cqrs-tale#23`, `logging-cache#26`).** Primary constructors and an
  `extension(IServiceCollection)` block for `AddSolCQRS`; no CQRS file exceeds 150 lines and no

Changes to the core brief's rows and new release-notes inputs for release 05:

- **L-01 (as delivered):** Warning, EventId 2149, the template above; the activity status is
  `Error`. A request rejected by `FluentValidationPipelineBehavior` is a failed `Result` too, so
  validation failures now write this Warning entry (with `ErrorType` `ValidationError`) instead of

- **L-03:** unchanged for CQRS (no unbracketed placeholder found).

  throw in a behavior or event handler surfaces as the original exception instead of

  to the handler matching the `Send` overload instead of always to the query handler.

## Deviations

- **Step 02 — synchronous-throw tests.** A handler's synchronous throw was never wrapped (the
  compiled dispatcher calls it inside an async lambda), so `Send_HandlerThrowsSynchronously_*` is a
  regression pin and `Send_BehaviorThrowsSynchronously_*` is the test that failed before the fix.
- **Step 02 — dispatch technique.** Behaviors and event handlers are invoked by delegates created
  with `MethodInfo.CreateDelegate` from a generic method that casts to the interface (new internal
  `PipelineBehaviorInvoker<TResponse>`, a static cache in `EventDispatcher`), not by expression
  trees; the handler interface comes from the `Send` overload. The event-dispatch fix is pinned in
  `NotificationDispatcherTests`, and the test project gained `DispatchTestFixtures.cs` and
  `RecordingLoggerProvider.cs`.
- **Step 03 — test file and emitter location.** `LoggingPipelineBehaviorTests.cs` already existed
  (logging 05) and was extended. The `[LoggerMessage]` emitter is internal to CQRS
  (`OperationResultLogMessages`) because a Logging-owned one would need a new public member that no
  `C-nn` covers; Logging is unchanged. Status text `[FAIL]` matches the exception entry.
- **Step 05 — verification and page shape.** Snippet verification is recorded here instead of a PR
  description (direct commits to `master`): the 11 C# blocks of `docs/CQRS.md` were built in a
  throwaway `Microsoft.NET.Sdk.Web` project (for `builder.Services`) referencing
  `SolTechnology.Core.CQRS` and `SolTechnology.Core.Testing`, with global usings and stubs for the
  consumer types; 0 warnings, 0 errors, no `// illustrative` needed. The testing snippet's body ran
  and passed, and an unregistered query printed the documented missing-handler message. The RM-15
  note in `docs/Log.md` has no C# snippet. The page was rewritten into the canonical public
  documentation sections; the `#result-pattern` anchor that `README.md` links to was kept.
- **Step 06 — extra conformance and checks.** The internal `RequestDispatcher` also got a primary
  constructor. A tuned placeholder regex covered `[LoggerMessage]` templates. RM-16 applied: step 06
  changed no test file. The primary-constructor commit `dafd2001` was committed after the CQRS tests
  only; the full suite ran green before the next commit.
- **Step 06 — kept the joke (user decision 2026-11-03).** The planned removal of `//I'm just void`
  from `Nothing.cs` (`357f9422`) was reverted by a follow-up commit; Coding Guide §9.10 now
  exempts jokes.
