# SolTechnology.Core 2.0 — HTTP

> Historical delivery record. It may not describe the current system.

## Goal

Deliver the 2.0 hardening of `SolTechnology.Core.HTTP` end-to-end, as one library of the SolTechnology.Core 2.0
flagship release. Success means:

- POST and PATCH are never retried after an exception or timeout (`S3`, P-10).
- The request pipeline, the upstream health check, and options validation are correct (`http-api#5`, `#6`, `#8`, `#9`, `#15`–`#17`, L-02).
- `HttpClientExtensions` lives in `SolTechnology.Core.HTTP`, the upstream health check uses `IHttpClientFactory`, and `RequestBuilder` verbs drop the `Async` suffix (`C-10`…`C-12`).
- HTTP ships XML docs, `docs/Clients.md` and `docs/HTTP-Production-Checklist.md` that compile against 2.0, conforms to the Coding Guide, and logs with `[{Placeholder}]` templates.

## Code review fixes (2026-11-03)

An independent code review of `da1dbf2b..7d61e2fb` (steps 01–10) found three major and four minor
issues. All are fixed in commit `5a4378fc`; every test named "fail-before" failed on `7d61e2fb`
(18 failures in `tests/SolTechnology.Core.HTTP.Tests`) and passes after the fix.

1. **Policy ranges let Polly-invalid values through start (major).**
   **Finding:** `HttpPolicyConfiguration` accepted `MaxRequestRetries = 0`, breaker windows below
   500 ms, `RequestTimeout` below 10 ms, and delays or timeouts above one day; `ValidateOnStart`
   passed and Polly 8 threw on the first request.
   **Fix:** `MaxRequestRetries = 0` means "no retries, keep the breaker": `HttpPolicyFactory` adds
   no retry strategy. The other ranges match Polly: `RetryInitialDelay` 0 ms and `RetryTimeout`
   1 ms to one day, `RequestTimeout` and `OverallRequestBudget` 10 ms to one day,
   `CircuitBreakerDelayDuration` and `CircuitBreakerSamplingDuration` 500 ms to one day.
   **Test:** `HttpPolicyConfigurationTests` starts a host at every boundary: values inside the range
   start and serve the first request (`MaxRequestRetries = 0` is fail-before), values outside fail
   start with `OptionsValidationException` (fail-before for the ten values Polly rejects and the old
   ranges accepted). `Configure_ZeroRetries_SendsOnce_AndKeepsCircuitBreaker` (fail-before).
1. **Caller cancellation opened the circuit (major).**
   **Finding:** `IsTransientFailure` treated every `TaskCanceledException` as transient, so a
   caller's own cancellation counted towards opening the breaker and logged a retry warning and
   metric.
   **Fix:** the predicate receives the resilience context; an `OperationCanceledException` is
   transient only when the context's token is not cancelled, that is when it is a timeout.
   **Test:** `CallerCancellation_Burst_DoesNotOpenCircuit_NorRecordRetries` (fail-before; eight
   caller cancellations, then a successful call, no retry log, no retry metric);
   `HttpClientTimeout_TaskCanceledWithoutCallerCancellation_IsRetried` is the control.
1. **Open circuit mapped as non-recoverable (major).**
   **Finding:** `ServiceCallErrorMapper.FromException` sent `BrokenCircuitException` to the
   "Unexpected service call error" fallback with `Recoverable = false`.
   **Fix:** a `BrokenCircuitException` arm (it also covers `IsolatedCircuitException`) after the
   `TimeoutRejectedException` arm returns `Error` "Upstream circuit open", `Recoverable = true`.
   **Test:** `FromException_OpenCircuit_Returns_Recoverable_UpstreamCircuitOpen` (both exception
   types, fail-before); `FromException_TimeoutRejected_StaysTimeoutError` is the control.
1. **Per-request policy overclaimed (minor).**
   **Finding:** the XML doc of `CreateRequest(path, policy)` said the resilience pipeline reads the
   per-request policy.
   **Fix:** the doc says only `IncludeResponseBodyInException` is honoured per request; `docs/Clients.md`
   says the same in its per-request policy section. Documentation only.
1. **Exception logged in a placeholder (minor).**
   **Finding:** the circuit-opened warning logged the exception in an `[{Exception}]` placeholder.
   **Fix:** `logger.LogWarning(args.Outcome.Exception, "Circuit breaker opened for [{ClientName}]",
   clientName)`; recorded as L-06 in the core brief.
   **Test:** `CircuitBreaker_Opened_LogsClientNameWithExceptionAsLogException` pins the template,
   the level and the exception argument (fail-before).
1. **Retry metric tagged `?` for exceptions (minor).**
   **Finding:** `OnRetry` read the method from the response, which an exception outcome lacks.
   **Fix:** the tag uses the same request-message lookup as the unsafe-verb check.
   **Test:** `Retry_AfterException_TagsRetryMetricWithRequestMethod` (`GET`, `PUT`; fail-before)
   listens on the retry counter.
1. **Bare catch in body capture (minor).**
   **Finding:** `TryReadCappedBody` swallowed every exception, and the deserialisation path read a
   body that the failed read had already consumed and the mapper ignores.
   **Fix:** the catch is narrowed to `HttpRequestException`, `IOException` and
   `ObjectDisposedException`; the deserialisation path passes `body: null` to the unchanged public
   `FromDeserializationFailure`.
   **Test:** `TryGet_ErrorBodyReadFailsUnexpectedly_Propagates` (fail-before);
   `TryGet_ErrorBodyReadFails_ReturnsStatusError` (three transport failures) is the control.
